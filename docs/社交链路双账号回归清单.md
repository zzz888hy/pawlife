# 社交链路双账号回归清单

好友 / 私聊链路的改动**必须用两个真实微信号**在真机上跑一遍才能算完成。
过去几轮反复出现「对方收不到申请」「看不到消息」，根因几乎都是**云函数没重新部署**，而不是代码写错。

---

## 0. 部署前置（每次改完云函数必做）

改动 `cloudfunctions/` 下任何文件后：

1. 把该文件的 `BUILD` 常量 +1（`friend` / `user` / `login` 三个文件各有一处）。
2. 同步改 `src/services/cloud.ts` 里的 `EXPECTED_CLOUD_BUILD`。
3. 微信开发者工具里，右键对应函数目录 → **「上传并部署：云端安装依赖」**（不是「仅上传」）。
4. 重新编译前端：`npm run build:weapp`。

### 自检部署是否生效

小程序里进 **我的 → 关于PawLife → 检查更新**：

- 弹「云函数已是最新版本」→ 部署到位，可以开始测。
- 弹「云函数需要更新」→ 按弹窗里列出的函数逐个重新部署，再点一次。
- 显示「旧版代码（无版本号）」→ 该函数从来没部署过带版本号的版本，必须部署。

> 只要这一步没过，下面所有场景都不用测了，测了也是白测。

## 测试账号

| 账号 | 说明 |
| --- | --- |
| A | 你的主账号（微信开发者工具里的本人） |
| B | 另一个真实微信号（真机，不要用开发者工具的「多账号调试」以外的模拟） |

**两个账号都要先完成一次登录**（打开小程序首页即可），否则 `users` 集合里没有档案，搜不到也加不上。

## 场景 1：改昵称，对方能看到新的

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1.1 | A：我的 → 设置 → 个人资料 → 昵称改成「ZR」→ 保存 | 提示「已保存」，页面上昵称同步变成 ZR |
| 1.2 | A：重新进「设置」，看个人资料那行 | 显示 ZR（若显示「ZR1234」这类带数字的，说明昵称被占用，服务端自动加了后缀，属正常） |
| 1.3 | B：我的 → 好友 → 退出重进该页 | B 的好友申请列表里 A 显示为最新昵称，**不是**「宠物主人」 |

**失败排查**：1.3 显示旧名 → `friend` 云函数是旧版。1.2 显示旧名 → `user` 云函数是旧版。

---

## 场景 2：搜索并发出申请

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 2.1 | B：好友页搜索框输入「ZR」 | 搜到 A 的卡片，**头像正常显示**（emoji 或照片，不是 `cloud://...` 字符串） |
| 2.2 | B：点「＋ 加好友」 | toast「已向 ZR 发送申请」，按钮变成「已申请 · 点此重发」 |
| 2.3 | B：退出好友页再进来 | 按钮仍是「已申请 · 点此重发」（状态持久化正确） |

**失败排查**：2.1 搜不到 → A 没登录过，或 `user` 云函数是旧版。2.1 头像乱码 → `friend` 云函数是旧版。

---

## 场景 3：对方收到申请并同意

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 3.1 | A：好友 → 好友申请 tab | 看到 B 的申请，昵称/头像正确，tab 上有红色角标 |
| 3.2 | A：点「同意」 | toast「已通过 xx 的申请」 |
| 3.3 | A：切到「我的好友」tab | B 出现在列表里，按钮是「私聊」 |
| 3.4 | B：好友 → 退出重进 →「我的好友」 | A 出现在列表里 |

**失败排查**：3.1 空 → 走一遍场景 0 的自检；若自检 OK 仍然空，进云开发控制台看 `friendRequests` 集合里有没有 `toOpenid` = A 的 openid、`direction` = `outgoing` 的记录（有说明 B 发出去了，是 A 侧接收问题；没有说明 B 侧发送失败）。

---

## 场景 4：私聊真正互通（本轮重点）

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 4.1 | B：我的好友 → 点 A →「私聊」 | **能进入聊天页**，顶部显示 A 的昵称，不是只有「私聊」标题的空页 |
| 4.2 | B：发一句「在吗」 | 消息出现在自己气泡里，**不再自动回一条** |
| 4.3 | A：打开和 B 的私聊 | **看到 B 发的「在吗」** |
| 4.4 | A：回一句「在的」 | A 自己能看到 |
| 4.5 | B：停在聊天页不动，等 3~5 秒 | B 页面上**自动出现** A 的「在的」 |

**失败排查**：

- 4.1 是空页 → 好友关系没建立（回场景 3）。
- 4.2 冒出自动回复 → `friend` 云函数是旧版，`sendMessage` 还在走 `autoReply` 分支。
- 4.3 A 看不到 → 共享会话没生效，同样是 `friend` 云函数旧版。
- 4.5 不刷新 → 前端没重新编译（轮询是前端改动）。

> ⚠️ 只有跟**种子宠友**（小鹿、阿橙这些演示好友）聊天才会有自动回复，那是刻意保留的演示行为。
> 跟真实用户聊天出现自动回复 = bug。

## 场景 5：照片头像跨用户可见

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 5.1 | A：我的 → 点头像 → 上传一张真实照片 | 上传成功，A 自己看到照片头像 |
| 5.2 | B：好友页搜索 A | 看到的是**照片**，不是乱码 |
| 5.3 | B：进和 A 的私聊页 | 顶部和消息气泡里的头像都是照片 |

**失败排查**：显示成 `cloud://cloud1-xxx/...` 长串 → 该处没走 `isImageUrl` 判断，或云函数没做 `cloud://` → 临时链接转换。

---

## 已知的刻意保留行为（不是 bug）

- 种子宠友（小鹿 / 阿橙 / 草莓 / 阿树）会自动回复 —— 演示用的假好友。
- 昵称被占用时服务端自动追加 4 位数字 —— 保证昵称唯一，见 `user` 云函数的 `nickSuffix`。
- 真实用户的距离显示为空 —— `users` 集合里只有 `location` 坐标，没有预存的 `distance` 字符串。
